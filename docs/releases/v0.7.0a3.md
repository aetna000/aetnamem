# AetnaMem 0.7.0a3 — activation works after rollback

Status: **experimental Python prerelease**

This patch fixes the dashboard error:

```text
cannot move directly from off to active
```

## Cause

Rollback correctly restored OpenClaw and left the legacy trial mode `off`.
The dashboard still had a verified, searchable mirror and correctly offered
**Activate AetnaMem**, but the old internal transition table required an
invisible intermediate `capture` step. The native cutover could finish its
checks and then be rejected by that final state transition. AetnaMem restored
OpenClaw automatically, so memory was protected, but activation did not
complete.

## Fix

- A legacy `off` trial may now transition directly to `active`.
- CLI status now tells a ready `off` trial to inspect and activate its
  preserved mirror instead of incorrectly telling the user to start over.
- The direct transition still runs the existing readiness gate: the evidence
  chain must verify and a synchronized native mirror or approved memory must
  exist.
- OpenClaw activation still verifies the final mirror, byte-for-byte frozen
  snapshot, configured capability boundary, gateway RPC, `memory_search`,
  `memory_get`, and capture/injection hooks.
- The regression suite now covers active → off → active as well as the full
  native activate → rollback → activate → rollback lifecycle.

No npm code changed. The matching bridge remains
`openclaw-memory-aetnamem@0.5.0-experimental.1`.

## Update

```bash
python -m pip install --upgrade --pre aetnamem==0.7.0a3
aetnamem dashboard daemon restart
aetnamem dashboard daemon open
```

# AetnaMem 0.5.2 — Multimodal memory with evidence

Status: **release**

> **AetnaMem turns multimodal agent observations into governed, searchable,
> and auditable memory.**

A multimodal agent may see an image, hear a voice note, inspect a video, or
read a document. AetnaMem 0.5.2 gives the resulting text observation a durable
evidence envelope: what exact byte stream it came from, where the host keeps
it, which extractor produced it, whether a person approved it, and what was
later deleted.

AetnaMem does not store or analyze the original media. The host remains
responsible for media access, extraction, authorization, and deletion.

## Install

The Python package name and normal installation path have not changed:

```bash
python3 -m pip install --upgrade aetnamem
```

For the native OpenClaw integration:

```bash
openclaw plugins install npm:openclaw-memory-aetnamem@0.3.1 --pin
```

Python `0.5.2` is paired with OpenClaw plugin `0.3.1`.

## Added

- `Memory.remember_observation()` for one deterministic, quarantined text
  observation from an image, audio, video, or document extractor.
- First-class `media_artifacts` and `media_observations` rows with indexed
  subject and exact-byte SHA-256 relationships.
- Typed provenance for modality, host reference, segment, extractor
  provider/model/version, optional model digest, observed time, and
  extractor-local confidence.
- Lineage-aware re-extraction: the same artifact, segment, and extractor
  supersede an older unapproved observation; independent extractors
  accumulate.
- Promotion that closes the same-extractor lineage without allowing a
  quarantined observation to displace approved memory.
- Media provenance in recall, memory lists, inspection, audit search, and
  chronological trace output.
- `Memory.forget_artifact()` with an exact-artifact deletion receipt.
- CLI commands `aetnamem observe` and `aetnamem forget-artifact`.
- MCP tools `memory_observe` and `memory_forget_artifact`, bringing the
  default catalog from 15 to 17 tools.
- OpenClaw tools `aetnamem_observe` and `aetnamem_forget_artifact` in npm
  `0.3.1`.

## Trust and policy

- Every observation starts `quarantined`.
- Extractor confidence is evidence only. It cannot rank, promote, or authorize
  a memory.
- Generic CLI and MCP calls are marked `caller_asserted`; they cannot claim
  that AetnaMem or a trusted host verified media bytes.
- `verified_by_aetnamem` is reserved and rejected because this release does
  not accept and hash media streams itself.
- An observation remains informational memory, never action authority.

## Deletion boundary

`forget_artifact` resolves indexed relationships from one artifact digest to
every derived observation, record, episode, graph object, and registered
semantic vector. It purges content, verifies the live database state inside
the transaction, and returns
`aetnamem-artifact-deletion-receipt-v1`.

The receipt is intentionally narrow:

- SHA-256 identifies one exact byte stream, not every visual or acoustic copy.
- A resized, transcoded, or re-encoded copy has another digest.
- AetnaMem deletes its derived memory, not the host's original file, backups,
  snapshots, or replicas.
- Immutable audit events and tombstones retain identifiers and cryptographic
  digests, not the deleted observation text or host reference.

## Compatibility

- `pip install aetnamem` remains the installation command.
- Existing Python `Memory` methods, CLI commands, SQLite records, and the
  original 15 MCP contracts are unchanged.
- Database migration is additive; existing databases gain the two media
  provenance tables automatically.
- Text-only agents continue to work exactly as before.
- Semantic investigation still embeds canonical text only; this release does
  not add media embeddings.
- Hosts are not required to use the new media tools.

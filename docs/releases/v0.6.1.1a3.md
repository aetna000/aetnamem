# AetnaMem 0.6.1.1a3 — preserve the OpenClaw memory contract

Status: **experimental preview**

This prerelease closes a cutover gap found while testing the OpenClaw
shadow-and-takeover flow. Earlier takeover code replaced the native storage
but did not preserve OpenClaw's standard agent-facing memory tools.

Matching packages:

- Python: `aetnamem==0.6.1.1a3`
- OpenClaw bridge: `openclaw-memory-aetnamem@0.4.1-experimental.3`

Install the engine; let it install the matching bridge:

```bash
python -m pip install --pre aetnamem==0.6.1.1a3
aetnamem --version
aetnamem openclaw install
```

## What changed

- Active takeover now registers OpenClaw-compatible `memory_search` and
  `memory_get` schemas in addition to AetnaMem's explicit tools.
- Search returns the real audited AetnaMem rank score and a stable
  `aetnamem://record/...` lookup path.
- Exact record reads and reads of frozen `MEMORY.md` / `memory/*.md` sources
  are added to the audit chain.
- Frozen source reads verify the original SHA-256 before returning text.
- Activation inspects the loaded OpenClaw runtime after restart and requires
  both compatibility tools plus the capture, injection, and history-cleaning
  hooks. Failure triggers automatic restoration.
- Activation refuses a switch when explicit native session search, extra
  paths, wiki memory, qmd, multimodal indexing, dreaming, or active-memory
  configuration would otherwise be lost.
- The conversation-access permission required for post-turn capture is
  explicitly reasserted during activation.

## Boundaries

This remains experimental. AetnaMem replaces the default supplemental
Markdown memory path; it does not claim parity with every optional OpenClaw
memory extension. Unsupported configured capabilities stop the switch instead
of being silently removed. OpenClaw continues to own identity, authorization,
tools, skills, transcripts, provider logs, and execution.

# AetnaMem 0.7.0a6 — inspect and approve the memory evidence

Status: **experimental prerelease**

Matching bridge: `openclaw-memory-aetnamem@0.5.0-experimental.4`

This prerelease makes the OpenClaw shadow-and-takeover workflow substantially
more inspectable. It turns the dashboard into an investigation and approval
surface, binds uploaded media to exact host bytes, and preserves the evidence
needed to distinguish a candidate, a retrieval attempt, an actual context
delivery and the later agent response.

## OpenClaw adoption path

- The engine still owns bridge installation. Users install AetnaMem with pip
  and run `aetnamem openclaw install`; they do not need to install npm directly.
- `openclaw aetnamem dashboard` starts the local dashboard when needed and
  opens its protected URL in the system browser.
- The daemon stores one high-entropy access key in its mode-`0600` state. The
  protected launch URL remains valid across normal restarts; removing the
  daemon rotates the key without deleting memory or evidence.
- The dashboard remains a two-state product surface: OpenClaw active while
  AetnaMem mirrors, or AetnaMem active after a verified cutover. Restore makes
  the frozen native memory authoritative again.

## Auditor dashboard

- A global Audit Explorer searches the complete evidence chain with combined
  full-text, time, event-type, actor, session and record filters.
- Investigators can inspect a histogram, page with stable cursors, pivot from
  events into records and sessions, save local views, and export CSV, JSON,
  NDJSON or formatted text.
- Exact retrieval and context-event identifiers now travel through the bridge
  to the digest-only response binding. Candidate-only retrievals are not
  presented as deliveries.
- Record history keeps the source, interpretation, admission, recall, context
  injection and response stages readable, while missing legacy evidence is
  explicitly marked rather than inferred.

## Governed uploaded-media observations

- The OpenClaw bridge consumes typed `message_received` attachment metadata,
  accepts only regular files under OpenClaw's managed media directory, and
  streams the exact bytes through SHA-256. It stores no media bytes or absolute
  local path in AetnaMem.
- The current attachment digest is bound to the current session and cleared so
  a later text-only message cannot accidentally reuse stale media provenance.
- `aetnamem_observe` uses that verified binding and an exact schema for segment
  and extractor metadata. Unexpected nested fields cannot leak through an
  over-broad tool schema.
- Image approval shows the digest-verified source beside the exact generated
  description. **Approve description as memory** makes only that text eligible
  for recall. **Reject and purge** removes the candidate and derived indexes.
- If the host image is missing or its bytes no longer match the recorded
  digest, the dashboard disables approval. The original host file remains
  OpenClaw-controlled in either case.

## Security and evidence boundary

The dashboard remains loopback-only and requires its HttpOnly session cookie,
same-origin request, CSRF token and exact record confirmation for mutations.
The preview endpoint serves only a quarantined image found beneath OpenClaw's
managed media root after a streamed SHA-256 match. Approval does not retrain a
model, store image pixels, or prove that the description is correct; it records
that a local reviewer accepted that exact description as recallable memory.

The evidence chain proves recorded ordering and identity. It does not claim
that a delivered memory caused an answer or improved task quality.

## Install

```bash
python -m pip install --upgrade --pre aetnamem==0.7.0a6
aetnamem --version
aetnamem openclaw install
aetnamem dashboard daemon restart
aetnamem dashboard daemon open
```

`aetnamem openclaw install` installs and verifies the matching npm bridge
internally. Direct npm installation remains a development and recovery path.

# AetnaMem 0.6.1.1a1 experimental preview — the engine installs its OpenClaw bridge

Status: **experimental prerelease; not the final 0.6.1.1 release**

Version 0.6.1.1a1 previews a fix for a confusing installation boundary in
0.6.1. The
OpenClaw npm package is a JavaScript bridge, not the AetnaMem engine, but
OpenClaw could install that bridge successfully when the Python engine was
missing. The package looked installed even though memory could not operate.

The supported customer path is now:

```bash
python -m pip install --pre aetnamem==0.6.1.1a1
aetnamem --version
aetnamem openclaw install
```

Users do not install the npm bridge directly. `aetnamem openclaw install`
owns the complete operation:

1. Locate and run the current `aetnamem` executable.
2. Locate and verify the OpenClaw CLI.
3. Install or upgrade the matching pinned npm bridge.
4. Verify that OpenClaw retained the expected bridge version.
5. Store the engine's absolute executable path in OpenClaw configuration.
6. Start Safe Switch in capture-only mode.
7. Restart OpenClaw and require a successful gateway RPC probe.
8. Verify the retained engine path and fail-closed Safe Switch configuration.

The resulting state writes local trial candidates but does not change model
context and does not add provider calls. The next command is:

```bash
aetnamem trial dashboard
```

## Failure and rollback

The installer snapshots the pre-install plugin entry and detected bridge
version. If installation, configuration, restart, or verification fails, it:

- moves any newly created trial to `off`;
- restores or removes the bridge package according to the prior state;
- restores the prior `plugins.entries.memory-aetnamem` configuration; and
- restarts the gateway again.

If any rollback step also fails, the CLI reports that failure explicitly
instead of claiming restoration.

## Bridge hardening

OpenClaw plugin `0.4.1-experimental.1` now performs an MCP engine handshake
when its service
starts. A missing executable produces an actionable error containing the
Python installation command, version check, and absolute-path option.

Direct `openclaw plugins install` remains documented only for repository
development and manual recovery. OpenClaw deliberately disables npm lifecycle
scripts for untrusted plugin installation, so the bridge cannot safely install
Python from an npm `postinstall` hook.

## Other changes included

- `aetnamem --version` reports the installed Python distribution version.
- Safe Switch lifecycle commands default to human-readable output; `--json`
  remains available for automation.
- The functional visual Safe Switch dashboard replaces the old raw-JSON
  fallback page.
- Rollback output distinguishes restoration of an enabled pre-trial plugin
  from disabling AetnaMem.

## Package versions

- PyPI prerelease: `aetnamem==0.6.1.1a1`
- npm experimental tag: `openclaw-memory-aetnamem@0.4.1-experimental.1`

The Python API, generic CLI/MCP interfaces, existing SQLite databases, and
normal non-trial OpenClaw configuration remain compatible.

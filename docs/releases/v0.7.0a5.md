# AetnaMem 0.7.0a5 — model-semantic memory with an auditor evidence chain

Status: **experimental prerelease**

Matching bridge: `openclaw-memory-aetnamem@0.5.0-experimental.3`

This prerelease closes two gaps found during live OpenClaw testing. Durable
memory admission now uses OpenClaw's selected model to interpret the current
user's intent instead of scraping a transcript or guessing from keywords. The
dashboard now turns every memory record into a navigable investigation rather
than showing an unexplained internal ID.

## What changed

- Active takeover stages OpenClaw's typed current-user prompt for a short,
  session-bound handoff. The existing OpenClaw model calls `memory_remember`
  with one concise durable fact; AetnaMem records the model identity, source
  digest, interpreted-fact digest and binding assurance.
- AetnaMem makes no additional model call. Tool output, retrieved pages,
  quoted text and agent guesses cannot use the trusted typed-user path.
- Active takeover no longer scrapes rendered transcripts. Shadow mode mirrors
  the native memory files that OpenClaw itself chooses to write.
- Dashboard search record IDs now open a complete auditor view: source and
  interpreter, lifecycle, scored retrieval attempts, context-injection
  receipts, digest-only response bindings and chronological audit events.
- Investigation reports download as formatted text or JSON. A tombstoned
  record exposes its reconstructed, hash-bound deletion receipt.
- After a memory is injected, the bridge may bind it to the SHA-256 digest of
  the later assistant response. The response body is not stored. This proves
  delivery-before-response, not causal impact or answer quality.
- Historic gaps are explicit: the UI says `not recorded` instead of inventing
  an interpreting model, injection, response or deletion event.

## Evidence boundary

The audit chain proves which source was admitted, which record was considered,
which IDs entered context and which response fingerprint followed when those
receipts exist. It does not prove that a memory caused the response, improved
the answer or reduced cost. Those remain Memory Impact research questions.

## Install

```bash
python -m pip install --upgrade --pre aetnamem==0.7.0a5
aetnamem --version
aetnamem openclaw install
aetnamem dashboard daemon restart
aetnamem dashboard daemon open
```

Users install through the Python command. It installs and verifies the matching
npm bridge; direct npm installation remains a development/recovery path.

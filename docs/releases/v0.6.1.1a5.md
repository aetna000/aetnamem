# AetnaMem 0.6.1.1a5 — fresh dashboard login after restart

Status: **experimental preview**

This prerelease fixes one dashboard-daemon restart defect found immediately
after `0.6.1.1a4`.

The dashboard log is append-only. Previously, `daemon restart` could read the
old process's already-consumed login URL before the new process wrote its
fresh one. The daemon appeared healthy but opening the reported link returned:

```json
{"error": "invalid login code"}
```

`0.6.1.1a5` records the log end before launching the new process and accepts a
login URL only from bytes written after that boundary. A regression test
reproduces the consumed-code case.

## Update

```bash
python -m pip install --upgrade --pre aetnamem==0.6.1.1a5
aetnamem dashboard daemon restart
```

The new `Open` URL is generated by the current daemon process. Existing
memory, mirrors, snapshots, and audit evidence are preserved.

The two-state dashboard and all other `0.6.1.1a4` changes remain unchanged.
The compatible npm bridge remains
`openclaw-memory-aetnamem@0.4.1-experimental.3`.

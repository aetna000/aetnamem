# AetnaMem 0.7.0a1 — trustworthy OpenClaw activation and rollback

Status: **experimental preview**

Long OpenClaw operations no longer look frozen.

## CLI installation

`aetnamem openclaw install` now prints eight real workflow stages:

```text
[###-----------------] 1/8  Checking AetnaMem and OpenClaw
[#####---------------] 2/8  Reading the current OpenClaw configuration
[########------------] 3/8  Installing the verified OpenClaw bridge
...
[####################] 8/8  Verifying the memory mirror and audit evidence
```

The stages are emitted to stderr so `--json` remains clean machine-readable
output. If installation fails, the progress output explicitly says that the
prior state is being restored.

## Dashboard operations

Mirror refresh, AetnaMem activation, and OpenClaw restore now show:

- an animated progress bar;
- the current operation in plain language;
- elapsed seconds;
- an honest warning when gateway restart and verification may take a minute;
- disabled action buttons until the operation completes.

The bar is intentionally indeterminate because OpenClaw restart and filesystem
copy time cannot be converted into an honest percentage. It shows liveness
without inventing precision.

The terminal activation and rollback commands also report their real stages.
Machine-readable `--json` output remains free of progress text.

## Active takeover memory contract

The matching OpenClaw bridge is `0.5.0-experimental.1`. During verified
takeover it adds pinned system guidance telling the agent that AetnaMem is the
durable-memory provider. The agent must use `memory_search` and `memory_get`
and must not recreate or inspect `MEMORY.md` or `memory/*` through Bash. This
overrides OpenClaw's native workspace instructions, which otherwise continue
to tell the agent to edit those files after the native memory slot is disabled.

`aetnamem trial status` also no longer crashes while displaying an active
provider.

## Rollback does not fail on recreated files

If OpenClaw or an agent recreates `MEMORY.md` or `memory/*` after activation,
rollback now moves those divergent files into the trial evidence directory
before restoring the verified native snapshot. It records their original
relative paths and hashes. Nothing is silently overwritten, and the recreated
paths no longer block restoration.

The trial remains active until native restoration succeeds. A failed restore
therefore cannot falsely report that AetnaMem is already off.

Memories admitted while AetnaMem is active are returned to OpenClaw during
rollback in a deterministic, hash-verified Markdown file under `memory/`.
The rollback receipt identifies the exported record IDs, native path, and
content digest.

## Release gates

This preview is accepted only when a clean OpenClaw test proves:

1. installation, activation, and rollback all display progress;
2. activation verifies the gateway, `memory_search`, `memory_get`, and capture
   hooks before reporting success;
3. the post-switch agent uses AetnaMem memory tools without trying to read the
   intentionally absent native memory paths;
4. rollback restores the frozen files and preserves any divergent files
   created during takeover.

## Clean OpenClaw validation

The 2026-07-31 release-candidate test used OpenClaw `2026.7.1-2` and a clean
AetnaMem installation:

- native OpenClaw created the `marigold` baseline, with one Bash failure in its
  own memory-writing turn;
- installation displayed all eight stages and verified the bridge, gateway,
  baseline, mirror, and audit chain;
- activation displayed all eight stages and verified `memory_search`,
  `memory_get`, and all three capture/injection hooks;
- active recall returned `marigold` with no Bash or filesystem calls and no
  tool failures;
- active capture admitted the new `saffron` memory while native memory paths
  remained absent;
- rollback was tested after deliberately recreating both native paths. It
  preserved both divergent paths, restored the frozen originals, returned the
  `saffron` record in a hash-verified native export, and passed gateway
  verification.

This is an integration acceptance test, not a claim that no future model can
ever ignore system guidance. The runtime verifies its tools and hooks, and the
test demonstrates the expected behavior on the stated OpenClaw build.

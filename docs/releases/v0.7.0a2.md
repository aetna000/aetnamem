# AetnaMem 0.7.0a2 — reliable local dashboard access

Status: **experimental Python prerelease**

This patch fixes the dashboard-daemon authentication failure in `0.7.0a1`.
The old daemon advertised a one-time login URL even after the code had been
consumed. Reopening the recorded link could therefore return
`authentication required` or `invalid login code` although the daemon was
healthy.

## What changed

- One high-entropy access key now remains valid for the lifetime of one daemon
  process. Opening the access URL again creates a fresh HttpOnly browser
  session instead of failing with a stale code.
- `aetnamem dashboard daemon open` launches the recorded protected URL with
  the operating system's browser launcher. This avoids chat and editor link
  handlers opening the URL inside VS Code.
- `daemon start` now succeeds only after the child process publishes a usable
  access URL. If that does not happen within the startup deadline, AetnaMem
  stops the child and reports the daemon log instead of leaving a half-started
  service.
- `daemon restart` generates a new key, invalidating the prior URL and browser
  sessions.
- A completed, verified rollback is now a valid starting point for a later
  activation. Earlier cutover receipts and frozen snapshots move into a local
  evidence history instead of blocking the next switch.
- If a process actually stopped during cutover, the dashboard says that an
  interrupted switch was found, changes the action to **Restore OpenClaw**,
  and explains that restoration verifies the preserved files before another
  activation. It no longer presents a dead-end “roll back first” error.

## Security boundary

This is not an unauthenticated localhost server. The access URL is stored in
daemon state and startup log files that are both forced to mode `0600`; the
server binds only to `127.0.0.1`.
After access, the browser still uses an HttpOnly SameSite cookie. Mutations
still require CSRF and Origin validation. Anyone who can read these protected
files already has the privileges of the local OS account running AetnaMem.

## Use

```bash
python -m pip install --upgrade --pre aetnamem==0.7.0a2

aetnamem dashboard daemon restart
aetnamem dashboard daemon open
aetnamem dashboard daemon status
```

The matching OpenClaw bridge remains
`openclaw-memory-aetnamem@0.5.0-experimental.1`; no npm code changed in this
Python-only patch.

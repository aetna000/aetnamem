# AetnaMem 0.6.1 — Safe Switch beta

Status: **public beta; no universal performance claim**

Version 0.6.1 adds a reversible way to try AetnaMem beside an existing local
OpenClaw or Hermes agent before allowing memory to influence prompts.

The release is organized around one adoption path:

```text
capture → review → preview → bounded canary → activate
                                            └→ off / rollback
```

## Added

- `aetnamem trial start`, `status`, `candidates`, `approve`, `reject`,
  `preview`, `canary`, `activate`, `off`, `rollback`, `dashboard`, and a
  test-only candidate capture command;
- digest-bound `off`, `capture`, `preview`, `canary`, and `active` state;
- a separate SQLite trial database for candidates, previews, exposures,
  transitions, comparisons and host snapshots;
- candidate-only capture from authenticated user turns without raw-message
  retention;
- explicit human review before a candidate can be previewed or injected;
- preview manifests that record the query digest, candidate content digests,
  exact context digest and state revision;
- a bounded canary exposure counter;
- fail-closed behavior for missing, malformed or digest-tampered state;
- hash-chained mode transitions;
- OpenClaw Safe Switch hooks in npm plugin 0.4.0, with agent-callable AetnaMem
  tools disabled during a trial;
- a Hermes general-plugin adapter that coexists with its current memory
  provider;
- verified OpenClaw plugin-configuration snapshot/restore and Hermes plugin
  backup/restore;
- a loopback dashboard API with one-time sign-in, HttpOnly cookies, CSRF,
  Host/Origin checks, CSP and no-store responses.
- provider-neutral `use-governed-memory`, `audit-agent-memory`, and
  `trial-agent-memory` skills, plus Codex and Claude plugin manifests;
- deterministic skill wrappers that use only public AetnaMem CLI operations
  and require explicit confirmation for promotion, canary, activation,
  rollback, and deletion;
- a real, isolated OpenClaw/DeepSeek canary demonstration covering baseline,
  candidate review, exact preview, bounded exposure, activation, and verified
  rollback.

## What did not change

Installation remains:

```bash
pip install aetnamem
```

The Python `Memory` API, generic CLI/MCP tools, SQLite schema for normal
memory, four-memory runtime presets and existing non-trial OpenClaw behavior
remain compatible. Safe Switch is opt-in.

## Claim boundary

Safe Switch proves what AetnaMem captured, previewed, requested for exposure,
and restored. Those facts establish operational reversibility and traceability.
They do not prove that AetnaMem improved an answer.

The dashboard must label candidate/preview/exposure statistics as local
evidence, not causal impact. Paid paired replays are never triggered on
install. Memory Impact remains the separate research workflow for randomized,
host-verified performance studies.

## Start

```bash
python3 -m pip install --upgrade aetnamem
openclaw plugins install npm:openclaw-memory-aetnamem@0.4.0 --pin
aetnamem trial start --host auto
aetnamem trial dashboard
```

See the [Safe Switch guide](../safe-switch.md).

## Demonstration evidence

The checked-in
[77-second OpenClaw demonstration](../assets/demos/aetnamem-openclaw-safe-switch.mp4)
used:

- OpenClaw `2026.7.1-2`;
- DeepSeek `deepseek-v4-flash`;
- Python package `0.6.1`;
- OpenClaw plugin `0.4.0`;
- the installed `trial-agent-memory` skill.

On the single Atlas task, the baseline answered “I do not know yet” using
19,450 model tokens. The approved-memory canary answered “Kyoto” using 16,940
model tokens, 12.9% fewer in that run. One noisy candidate was rejected, one
clean candidate was approved, the exact 81-character context was previewed,
one canary exposure was recorded, activation succeeded, rollback restored the
host, and the five-event transition chain verified.

This is operational proof of the demonstrated flow and task result. It is not
a representative benchmark, held-out evaluation, or general causal claim.
See the [transcript and evidence boundary](../assets/demos/aetnamem-openclaw-safe-switch-transcript.md).
The matching [X article](../marketing/x-safe-switch-v0.6.1.md) uses the same
claim boundary.

## Validation at implementation time

- Python: **240 passed, 4 skipped**.
- Safe Switch-specific Python tests: state tampering, non-interference,
  approval/canary gates, private MCP surface, OpenClaw snapshot/restore,
  Hermes hook behavior and dashboard CSRF controls passed.
- OpenClaw npm 0.4.0: TypeScript build/typecheck, legacy/four-memory/Safe
  Switch hooks, setup tests and installed-server smoke passed.
- Python wheel and source archive built; an isolated no-dependency wheel
  install imported `TrialManager` and exposed `aetnamem trial`.
- Real OpenClaw skill installation, baseline, preview, one-turn canary,
  activation and rollback passed in an isolated Linux container.

Hermes clean-machine installation and a polished browser dashboard remain beta
gates. Version 0.6.1 ships the secured loopback dashboard API and UX contract;
it does not claim that the final visual dashboard is complete.

## Package versions

- PyPI: `aetnamem==0.6.1`
- npm: `openclaw-memory-aetnamem@0.4.0`

The npm plugin has its own compatibility version because it is a host adapter,
not the Python engine. Existing generic Python, CLI, MCP, and non-trial plugin
interfaces remain compatible.

# AetnaMem 0.7.0a4 — enforced OpenClaw memory takeover

Status: **experimental prerelease**  
Matching bridge: `openclaw-memory-aetnamem@0.5.0-experimental.2`

This prerelease fixes a takeover boundary discovered in a live OpenClaw test.
The previous bridge told the model not to access `MEMORY.md` or `memory/*`, but
OpenClaw's general Bash and file tools could still recreate those paths if the
model ignored the instruction. AetnaMem captured the user turn, yet OpenClaw
also wrote a duplicate native file.

## What changed

- Active takeover registers an OpenClaw `before_tool_call` guard.
- The guard blocks tool access to the exact frozen OpenClaw `MEMORY.md` and
  `memory/*` paths while leaving unrelated project files available.
- Activation records the exact protected workspace and now fails and restores
  the previous setup unless the runtime proves that the guard, capture hooks,
  recall hook, and compatibility tools are all loaded.
- Common authenticated statements such as `I like red apple` now become
  deterministic, searchable preference records instead of existing only as
  raw audited episodes.

The guard is defense in depth for ordinary OpenClaw tool calls. It does not
claim to sandbox arbitrary external processes outside OpenClaw or protect
paths that an administrator changes outside the verified takeover workflow.

## Install

```bash
python -m pip install --upgrade --pre aetnamem==0.7.0a4
aetnamem --version
aetnamem openclaw install
```

Users install through the Python command. It installs and verifies the matching
npm bridge; direct npm installation remains a development/recovery path.

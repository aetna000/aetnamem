# AetnaMem 1.0.0a3 — reliable semantic media memory for OpenClaw

Status: **experimental prerelease**

AetnaMem 1.0.0a3 fixes the OpenClaw path from an uploaded artifact to governed memory. The integration now treats memory requests by meaning rather than a keyword list, captures exact host-managed attachment provenance from OpenClaw webchat, and preserves that binding when OpenClaw runs hooks and tools in separate plugin runtimes.

## What changed

- OpenClaw guidance now distinguishes ordinary file creation from a semantic request to remember an uploaded image, audio clip, video, document, or derived observation.
- Paraphrases, indirect wording, slang, and profanity can express memory intent; the model is instructed to interpret the user's meaning instead of matching fixed phrases.
- When a request means both “create the file” and “remember it,” OpenClaw is instructed to perform both actions.
- Webchat attachment provenance is captured from OpenClaw's structured `MediaPath` and media-type fields. AetnaMem hashes the exact host-managed byte stream instead of guessing a file from text or scanning a directory.
- Attachment bindings are written atomically with owner-only permissions and can be resolved across separate plugin runtimes.
- Run-scoped bindings prevent an attachment from a previous turn being reused accidentally.
- Successful media admission now returns an explicit success signal while the observation remains quarantined until human approval.

## Install

Do not install the npm bridge separately. The Python installer pins and verifies the matching OpenClaw integration.

```bash
python -m pip install --pre aetnamem==1.0.0a3
aetnamem --version
aetnamem openclaw install
aetnamem dashboard daemon start
```

Packages:

- Python: `aetnamem==1.0.0a3`
- OpenClaw bridge: `openclaw-memory-aetnamem@1.0.0-experimental.3`
